# Mako 远景规划 — 差异化方向

## 市面竞品现状

| 项目 | 定位 | 局限 |
|------|------|------|
| Claude Code | 闭源、绑定 Claude、体验好 | 不可扩展、不开源、无评测 |
| Aider | 开源、专注 Git 工作流 | 无插件系统、无评测框架 |
| OpenHands (Devin 开源版) | 全栈 Agent、Docker 沙箱 | 太重、部署复杂 |
| Cline (VS Code) | IDE 插件形态、轻量 | 绑定 VS Code、不可独立运行 |
| LangChain/CrewAI | 通用 Agent 框架 | Python、不专注 Coding、无评测 |

## Mako 的差异化方向

### 方向 1：Agent 可观测性（Agent Observability）

**核心概念**：不只是让 Agent 跑起来，而是让你看清楚它在想什么、为什么这么做、哪里出了问题。

**具体能力**：
- 完整的执行 Trace（每一步的决策、工具调用、token 消耗）
- 决策归因（为什么选了这个工具而不是那个）
- 失败回放（失败时可以 replay 整个执行过程，定位问题）
- 实时可视化（Web Dashboard 看 Agent 的思考过程）

**价值**：模型训练团队最需要的就是"Agent 为什么失败了"——直接对接失败案例归因需求。

---

### 方向 2：Agent Benchmark 即服务（Eval-as-a-Platform）

**核心概念**：不只是一个 Agent，而是一个评测平台——任何人可以用它来评估任意模型的 Coding 能力。

**具体能力**：
- 标准化的评测任务格式（YAML 定义）
- 插件化的评分维度（正确性、代码质量、效率、最小修改）
- 一键多模型对比（同一任务跑 N 个模型，生成对比报告）
- 失败归因自动化（AI 分析失败原因，给出改进建议）
- 评测标准可配置、可插拔

**价值**：市面上没有开源的、开箱即用的 Coding Agent Benchmark 平台。"带着评测报告去模型团队"是核心成果。

---

### 方向 3：万物皆插件 + 插件市场（Plugin Ecosystem）

**核心概念**：把"万物皆插件"做到极致——不只是架构理念，而是一个可运营的插件生态。

**具体能力**：
- 任何人可以发布 Tool Plugin（如"Jira 集成"、"数据库操作"）
- 任何人可以发布 Skill Plugin（如"代码审查专家"、"重构助手"）
- 任何人可以发布 Eval Plugin（如"安全性评分器"、"性能评分器"）
- 插件之间可以组合（"代码审查 + Jira 集成 = 自动创建 Issue"）
- 插件市场（发现、安装、评分）

**价值**：网络效应——插件越多，平台越有价值。类似 VS Code Extension Marketplace 但面向 AI Agent。

---

### 方向 4：Agent 自进化（Self-Improving Agent）

**核心概念**：Agent 从自己的执行历史中学习，越用越好。

**具体能力**：
- 记录每次任务的成功/失败和策略
- 自动总结"什么场景用什么工具组合效果好"
- 下次遇到类似任务时，优先使用历史上成功的策略
- 轻量的"经验记忆"系统（不是微调模型，而是 prompt 层面的经验注入）

**价值**：目前所有 Agent 都是无状态的——每次从零开始。一个能"记住经验"的 Agent 是真正的创新。

---

## 落地节奏

| 阶段 | 时间 | 重点 |
|------|------|------|
| v0.1 | 已完成 | 核心循环（ReAct + Tool Use + Context） |
| v0.2 | 第 3-4 周 | 可观测性 + Skill/MCP + 插件系统骨架 |
| v0.3 | 第 5-6 周 | 评测平台（Benchmark + 评分 + 报告） |
| v1.0 | 第 7 周 | 发布 + 评测报告 + 文档 |
| v2.0 | 远期 | 插件市场 + Agent 自进化 |

## 核心叙事（面试/活水时怎么讲）

> "我做了一个开源的 AI Coding Agent 框架 Mako。它不只是一个 Agent 产品，更是一个评测平台。
> 
> 架构上采用微内核 + 万物皆插件的设计，核心稳定、能力可无限扩展。
> 
> 差异化在于：内置了 Agent 可观测性（能看清 Agent 为什么失败）和评测框架（能系统化评估不同模型的 Coding 能力）。
> 
> 我用它产出了一份 MiMo vs Claude vs GPT 的 Coding 能力对比报告，定位了模型的薄弱环节，给出了改进方向。"
