# Mako 远景规划 — 差异化方向

## 市面竞品现状

| 项目 | 定位 | 局限 |
|------|------|------|
| Claude Code | 闭源、绑定 Claude、体验好 | 不可扩展、不开源、无评测 |
| Aider | 开源、专注 Git 工作流 | 无插件系统、无评测框架 |
| OpenHands (Devin 开源版) | 全栈 Agent、Docker 沙箱 | 太重、部署复杂 |
| Cline (VS Code) | IDE 插件形态、轻量 | 绑定 VS Code、不可独立运行 |
| LangChain/CrewAI | 通用 Agent 框架 | Python、不专注 Coding、无评测 |

## Mako 的差异化方向

### 方向 1：Agent 可观测性（Agent Observability）

**核心概念**：不只是让 Agent 跑起来，而是让你看清楚它在想什么、为什么这么做、哪里出了问题。

**具体能力**：
- 完整的执行 Trace（每一步的决策、工具调用、token 消耗）
- 决策归因（为什么选了这个工具而不是那个）
- 失败回放（失败时可以 replay 整个执行过程，定位问题）
- 实时可视化（Web Dashboard 看 Agent 的思考过程）

**价值**：模型训练团队最需要的就是"Agent 为什么失败了"——直接对接失败案例归因需求。

---

### 方向 2：Agent Benchmark 即服务（Eval-as-a-Platform）

**核心概念**：不只是一个 Agent，而是一个评测平台——任何人可以用它来评估任意模型的 Coding 能力。

**具体能力**：
- 标准化的评测任务格式（YAML 定义）
- 插件化的评分维度（正确性、代码质量、效率、最小修改）
- 一键多模型对比（同一任务跑 N 个模型，生成对比报告）
- 失败归因自动化（AI 分析失败原因，给出改进建议）
- 评测标准可配置、可插拔

**价值**：市面上没有开源的、开箱即用的 Coding Agent Benchmark 平台。"带着评测报告去模型团队"是核心成果。

---

### 方向 3：万物皆插件 + 插件市场（Plugin Ecosystem）

**核心概念**：把"万物皆插件"做到极致——不只是架构理念，而是一个可运营的插件生态。

**具体能力**：
- 任何人可以发布 Tool Plugin（如"Jira 集成"、"数据库操作"）
- 任何人可以发布 Skill Plugin（如"代码审查专家"、"重构助手"）
- 任何人可以发布 Eval Plugin（如"安全性评分器"、"性能评分器"）
- 插件之间可以组合（"代码审查 + Jira 集成 = 自动创建 Issue"）
- 插件市场（发现、安装、评分）

**价值**：网络效应——插件越多，平台越有价值。类似 VS Code Extension Marketplace 但面向 AI Agent。

---

### 方向 4：Agent 自进化（Self-Improving Agent）

**核心概念**：Agent 从自己的执行历史中学习，越用越好。

**具体能力**：
- 记录每次任务的成功/失败和策略
- 自动总结"什么场景用什么工具组合效果好"
- 下次遇到类似任务时，优先使用历史上成功的策略
- 轻量的"经验记忆"系统（不是微调模型，而是 prompt 层面的经验注入）

**价值**：目前所有 Agent 都是无状态的——每次从零开始。一个能"记住经验"的 Agent 是真正的创新。

> "我做了一个开源的 AI Coding Agent 框架 Mako。它不只是一个 Agent 产品，更是一个评测平台。
> 
> 架构上采用微内核 + 万物皆插件的设计，核心稳定、能力可无限扩展。
> 
> 差异化在于：内置了 Agent 可观测性（能看清 Agent 为什么失败）和评测框架（能系统化评估不同模型的 Coding 能力）。

## 方向 5：多 Agent 协作（Multi-Agent）

**核心概念**：单个 Agent 处理复杂任务时能力有限，多个专业化 Agent 协作可以提升效率和质量。

**具体能力**：
- 主 Agent 可以委派子任务给专业 Agent（如"代码审查 Agent"、"测试 Agent"、"文档 Agent"）
- Agent 之间通过消息传递协作，各自有独立的上下文和工具集
- 支持并行执行（多个 Agent 同时工作）和串行编排（流水线模式）

**关于 A2A（Agent-to-Agent）协议**：
- Google 提出的 Agent 间通信标准协议
- 定义了 Agent 发现、任务委派、状态同步的标准格式
- 对于 Mako 当前阶段可能太重——我们的多 Agent 是进程内的，不需要跨网络通信
- 建议：先用轻量的进程内消息传递实现多 Agent，后续如果需要跨进程/跨网络再考虑 A2A

**落地路径**：
1. v0.4：进程内 Sub-Agent（主 Agent 委派子任务，共享 Tool Registry）
2. v0.5：专业化 Agent 预设（code-review-agent、test-agent、doc-agent）
3. v1.0+：可选 A2A 协议支持（跨进程 Agent 通信）

## 方向 6：用户画像自学习（User Profile Auto-Learning）

**核心概念**：Agent 在日常交互中自动学习用户的性格特征、编码偏好、决策风格，形成渐进式用户画像。每次启动时加载画像，无需用户反复重申自己的理念和偏好。

**业界现状**：
- Claude Memory：手动 + 自动记忆，但绑定云端账号
- ChatGPT Custom Instructions：手动填写，不会自动学习
- Cursor `.cursorrules`：纯手动，项目级别
- Kiro steering：纯手动

**Mako 的差异化**：
- **自动提取**：从对话中自动识别用户偏好（"别用 sed"、"用中文写文档"、"提交信息用英文"）
- **渐进式构建**：每次对话后增量更新画像，越用越准
- **本地存储**：画像存在 `.mako/user-profile.md`，用户可查看和编辑
- **透明可控**：用户随时可以查看 Agent 对自己的"理解"，删除不准确的条目

**具体能力**：
- 自动记录用户的技术偏好（语言、框架、工具链选择）
- 自动记录用户的沟通风格（简洁/详细、中文/英文）
- 自动记录用户的工作习惯（先测试后实现、先设计后编码）
- 自动记录用户的代码风格（命名规范、注释习惯、架构偏好）
- 提供 `mako profile` 命令查看/编辑画像
- 画像注入 system prompt，让 Agent "记住"用户

**落地路径**：
1. v0.5：基础画像提取（从对话中提取显式偏好声明）
2. v0.6：智能推断（从用户的修改行为中推断隐式偏好）
3. v1.0：完整画像系统（分类管理、置信度、过期机制）
